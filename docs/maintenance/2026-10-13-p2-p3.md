本次处理六小时维护台账中跳过的 M036、M006、M007。原六小时记录保持其当时的状态；以下为后续处理结果。

## M036 · P2 · 无 Web Locks 的跨页面竞争

- 状态：已增加安全互斥路径并验证，不再直接执行无锁持久写入。
- 新增 `site3/local-lock.js`：优先使用原来的 `rci:local-data` Web Lock；缺少 Web Locks 时，利用同源 IndexedDB 的重叠读写事务串行执行读取及提交。事务内持续排队读取请求，避免 promise 期间提前结束；不使用过期租约，不把个人记录迁入 IndexedDB。
- 事务中断会使保存检查失效；之后本页保持临时模式，不能把旧临时状态重新写回其他页面的新记录。关闭持锁页面后，浏览器释放事务，其他页面能继续。
- 两种安全锁均不可用时，现有持久记录保持原样；本页可以规划、收藏和导出，明确提示未保存，拒绝持久导入。原有 JSON 计划与备份格式不变。
- 计划确认框与课程数据的网络加载在临界区外；确认期间其他页面仍可操作，原有快照检查继续拒绝过期确认。
- 升级前打开的旧版本页面需刷新后加入新互斥协议；此次不宣称能够约束旧脚本或其他不参与协议的写入者。
- 标准依据：[IndexedDB transaction scheduling](https://w3c.github.io/IndexedDB/#transaction-scheduling)。
