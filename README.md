# TUM RCI All-in-One

## [打开学生网站 → tum-rci-all-in-one.vercel.app](https://tum-rci-all-in-one.vercel.app/)

给 TUM RCI 同学的中文日常入口。独立学生社群项目，不隶属于 TUM。

## 第一版，只做好两件事

**常用网站入口**：打开首页就能找到 TUMonline、Moodle、Matching、TUM Live 等平台。每个入口写清用途，点击卡片直接打开；按「上课与选课」「图书馆与校园」「科研与协作」「咨询与支持」直接分区展示，支持用途搜索。已收藏的网站卡片直接展示在首页顶部，点击即可打开；下方继续按模块展示全部网站。

图书馆入口直达 OPAC 检索和 anny 预约登录，卡片另有官方预约说明；预约支持自习座位、小组讨论室与视频间。eAccess 用于校外读取已许可电子文献，dokumenTUM 提供馆藏纸本文献扫描申请步骤。首页另有论文题目平台、MATLAB 校园许可、TUM ShareLaTeX、LRZ GitLab、Sync+Share 和 GigaMove，卡片注明用途与登录条件，MATLAB 卡片另有官方激活与安装说明；来源台账记录公开核对范围。

首页「RCI 学业咨询」直达 RCI 专业页联系人区域，注明专业协调员与 rci@tum.de；沿用 R009 收藏编号。原 Informatics 总页以「Informatics 咨询总览（多专业）」保留在更多资料中，并说明其跨专业考试事务清单对 Master RCI 的例外。

另收录 MPIC 学生会课程评价查询、考试专用 Moodle、CIT 打印与扫描说明、英语写作辅导预约、Academic Coaching、文献管理校园许可、图书馆文献咨询和 ProLehre 学习方法。电脑端将论文入口区分为「研究组论文题目」（Thesis Management，参与平台的研究组）与「全校论文题目公告栏」（Themenbörse，跨学院发布），两者都不保证覆盖全部题目；原论文入口的收藏编号保留。图书馆预约也注明主校区 Presentation Lab 的演讲练习用途；需要个人登录或申请的服务，只核对公开入口，不转载个人结果。

**如何选课、如何规划学分**：先看懂学分结构，再找到课程，以横向学期看板分配课程，随时看每学期学分与整体缺口。支持四、五学期等不同节奏，选择起始冬夏季节，按目录季节检查安排。课程以目录原名显示，中文译名辅助理解，模块代码用于核对；类别保留分组字母与原名。实验课、研讨课和考试登记的办理路径分开说明。

首版 Goal：**让学生一打开就知道在哪里点，点完知道下一步做什么，能顺畅地找到常用网站并完成自己的选课与学分规划。** 验收以入口清晰和实际操作顺畅为准，功能或资料数量不作为产品完成标准。

[常用网站](https://tum-rci-all-in-one.vercel.app/) · [选课程](https://tum-rci-all-in-one.vercel.app/courses/) · [我的计划](https://tum-rci-all-in-one.vercel.app/planner/)

电脑和手机端统一通过「我的计划」顶部的「学分与学业规则」查看毕业学分、学期进度与第七学期完成机会、选课与考试报名、官方来源。完整规则从调整规划条件页移出；进度提示旁可直接打开对应章节，关闭后返回原学分检查。说明独立于个人计划读取，旧 `/study/` 链接在两端均进入统一说明，静态页面保留同源正文作为无需 JavaScript 的回退。此次仅调整入口与展示，不改变自动规划和学分计算逻辑。「学分概览」保留总学分、已通过与剩余数字，电脑端保留大块彩色色带，按各类目标学分占比分配长度，小学分类别保留文字可读宽度；模块名称与学分数居中直接显示在色带内，深色填充上使用白字、浅色区域使用同色系深字，留白与细描边标清每个模块的完整范围，深色填充表示已规划比例；手机端配合数字显示不同长度的进度条。未覆盖的学期进度收在一行详情入口中；第二学期末的 A/B/C 基础模块、第三至第六学期末的累计学分与差额直接标在对应学期旁。电脑和手机共用学分检查弹窗，可查看各类缺口、领域要求、当前规划范围内的学期检查点，并跳转到规则说明后返回。课程调整后同步更新，已覆盖的检查点不再提示；历史通过学期缺失时提示补全记录，不直接判定实际未达标。

手机端有固定的常用网站、选课指南、我的计划入口。加入课程后按钮和学分同步更新；二选一课程可以确认改选，移除课程可以撤销。

「选课程」输入名称或代码即搜索；必修、专业选修、跨学科可一键切换，季节、语言和计划状态收在更多筛选中。目标学期持续可见，课程旁直接加入或移到本学期，可连续选课并撤销。筛选和目标学期保留在网址中，清除筛选不会改动目标学期；手机端按单列显示。从列表进入详情后，页面返回和浏览器后退会恢复已加载的课程数量及原课程在屏幕中的位置，焦点也回到该课程。视图状态仅保存在当前标签页和浏览历史中，不写入个人计划；无法读取暂存时仍能按课程定位。

选课页标题旁显示入学时间，可直接设置或修改；手机端放在标题下方。搜索与目标学期栏保持对齐，入学时间弹窗提供前两个学期的季节预览。保存后同步更新各学期的冬／夏季和适用规则，保留已选课程、学期编号、已修记录、搜索与筛选；取消不会修改计划。入学时间已被其他页面修改时拒绝覆盖，其他页面新加的课程继续保留。

课程详情页先展示课程名称、中文简介和学分／开课季节／授课语言，再阅读上课与考核、选课要求和预计投入。电脑端把目标学期和加入计划放在右侧固定区域，手机端使用简介下方的紧凑操作区。具体先修、二选一、学分冲突和个人资格要求直接显示，旧版说明放在简介之前；重复的通用提示和没有数据的时间栏不显示。已知二选一、等价课程及同一计分组的其他版本提供名称、代码、学分和详情链接。可直接加入或移动课程，并撤销本次调整；已修和自录记录保护不变。本学期开课与官方课程介绍有独立入口，返回列表保留搜索和筛选。

`content/course-summaries.json`覆盖全部595条已收录课程，逐门整理原创中文简介、上课方式、考试方式及预计投入。593条对应官方模块手册（含补查的ED140014、MW2352、WI000159）；IN2404按2023年官方课程页补充内容和上课方式，IN9003仅按RCI法规附件补充上课和考试信息。549条有官方内容简介，45条手册没有内容字段，IN9003尚未找到课程内容，缺项明确显示、不按课程名称编写。教学、考核和时长独立处理；旧学期说明有醒目标记，ED150018、SZ0514的时长冲突不作为有效总投入发布。总投入是整个模块的估算，不是每周课时，不能代替本学期公告。

2026-10-17对全部595条课程分别记录大纲、学习目标和课堂活动的可用性：549条有中文大纲，547条有按官方学习目标整理的中文说明，522条有明确的课堂活动、练习、作业或项目说明。45份手册未提供课程内容，46份未提供学习目标，缺项不从课程名称推测；另2条官方备用来源没有单独的学习目标。项目和作业只取自教学或考核说明，不从学习目标反推必交任务；自愿、加分、提交比例与评分权重继续保留。页面按「课程大纲」「学完能做什么」「上课与考核」阅读，同一活动和评分句只展示一次。593份手册已重新读取，正文与整理依据一致；内容字段逐项匹配，可用`python3 scripts/verify_course_detail_fields.py --xml-dir /path/to/fresh-handbook-xml`复核，原文XML仅保存在仓库外。

课程详情顶部集中展示基础信息，正文按内容、考核、选课要求和学习投入分区，直接通过栏目标题阅读。电脑端规划操作在侧栏，手机端优先显示正文，通过「安排课程」直接跳转操作区。542门有可靠总时长的非论文课程同时提供每周参考，统一将总投入按15周均摊、保留一位小数，并注明包含上课与课外学习，项目和备考可能集中安排；这不是官方逐周课时。时长缺失或冲突不作换算，论文按实际写作周期安排。

`data/course-content-evidence.json`保存来源身份、原始响应与选用字段哈希、学期、缺项和冲突判断，不保存官方全文。构建时校验595条完整覆盖、来源与目录证据一致、字段可用性和时间分项，避免漏课或用空白字段生成简介。逐字段核查、哈希和对照日期不渲染到用户页面；会影响选课的先修、学分冲突、等价课程和资格限制继续直接显示。MA8113、IN3150、SOT56601、SOT82136继续按维护者要求排除。

个人计划和收藏自动保存在当前浏览器，无需登录。首页收藏区与「我的计划」中的「备份与迁移」可导出包含课程、学期安排、批次、补修设置和收藏的 JSON 文件，换设备后导入即可继续。导入先显示预览，默认合并并保留当前课程的安排与状态，也可选择替换。每次导入前保留一份本地恢复备份，最近 3 次记录可预览恢复。旧版计划文件仍可使用，不改变当前收藏；电脑端旧计划中缺少学期安排的未修课程放入第1学期，已修历史学期保留。

网站区旁的「缺少入口？」、桌面页头和全站页脚可进入快速反馈。先选择缺少入口、功能建议或使用问题，再填写简短描述；反馈直接提交到本站私有收件箱，无需账号，仅供维护者查看。保存成功后显示回执；失败时保留文字，可安全重试。只提交描述、类型和相关页面路径，不附带个人计划、收藏、搜索词或分享片段。

已有申请、科研、生活等资料保留在次级页面与更多资料中。后续按实际需求逐步完善。

## 首版验收路径

- 打开首页，能看懂常用平台的用途，一次点击进入原始网站。
- 收藏一个网站，立即看见它出现在首页顶部，点击卡片直接打开；原有收藏保留，取消收藏可以撤销。搜索无结果时能清除搜索继续使用。
- 从选课指南理解学分结构，进入课程目录，按课程名或代码找到课程。
- 选择四或五学期与起始冬夏季节，每学期一列，课程向下排列；卡片收起时保留名称、学分与简短状态；展开后在标题区查看中文参考名、课程代码与开课季节，课程详情位于标题区右侧，与课程代码和开课信息同层，「自动规划时保留此学期」以紧凑单行显示，已通过和移除操作分开；电脑端未修课程通过拖动安排学期，手机端保留学期选择，已通过课程保留历史学期修正，季节冲突提示继续显示；类别配色与顶部学分条联动保留。电脑端可在同学期内直接拖动排序，插入提示线显示在两张课程卡片之间。显示顺序独立保存，刷新、完整备份、分享链接和导出继续保留，学分计算与自动规划约束不变；新增或移入课程放在末尾，自动规划保留仍在原学期的手动顺序。电脑端可跨学期拖动，手机端点开课程选择目标学期，选完自动收起，支持撤销。标题和学分在滚动时持续可见，手机左右滑动查看其他学期、点课程调整。目录季节不符时先确认。
- 点学期卡片上的「添加课程」，直接打开选课面板。默认展示对应季节，可连续加入多门，学分即时更新；已有课程可直接移到本学期，也可撤销。电脑端缩短规划时，超出范围的未修课程移到第1学期，课程与学分保留。
- 点「一键规划」时按钮显示正在规划，计算和保存过程不打开预览窗口；成功后直接更新看板，只显示执行结果和撤销，不再提供方案预览或采用确认。只有缺少必要个人信息或规划失败时弹窗；条件图标只负责调整参数，面板中的一键规划同样直接执行。手动看板继续调整，实际课表到个人 TUMonline 查看。
- 手机端入口持续可见，操作不被浮栏遮挡；刷新后已有计划仍可继续。

首页「图书馆与校园」中的「食堂菜单」沿用普通入口卡片，支持搜索与收藏，优先恢复上次查看的食堂，可切换 25 个食堂与餐厅，通过周切换和每日卡片选择日期；不再显示单独的日历输入框，「今天」放在周切换栏中。菜品、价格与食材标记在打开页面时直接读取 TUM Developers eat-api；默认日期没有菜单时显示本周或下周最近一次已公布的菜单，并注明实际日期，手动选择的日期保留。中文菜名在上、德文原名在下，按重量计费与另加费用分开显示；供应、标记与收费以食堂现场为准。 食堂地址下方显示一行常规营业时间，连续相同的时段合并展示，周五等不同时段单独列出；切换食堂时同步更新，缺失时显示暂未提供。时段来自 eat-api 食堂目录，保存在各食堂的 `open_hours` 中，`opening_hours_checked_on` 记录 2026-10-18 的导入日期；它是目录快照，菜单每日同步不会更新此字段，也不用于推断实时营业或临时休息状态。

食堂列表和下方菜单标题的名字旁均显示当前人数小状态（与所选菜单日期无关），目前接入 eat-api 目录公布的 RedCube 接口：Mensa Lothstraße、Mensa Pasing、StuCafé Pasing。仅显示人数，不根据未经说明的 `percent` 字段猜测拥挤等级或等候时间；其他食堂隐藏此状态。Garching 的独立接口在 2026-10-18 测试时无法连接，暂未接入。上下状态由一个管理器维护，共用同一份人数数据、一个轮询调度和一个页面可见性监听；只刷新发生变化的状态文字。列表搜索、校区筛选或切换食堂不会重复请求；可用来源在页面打开时一并读取。浏览器通过同源 `/api/mensa-crowding/` 读取固定白名单接口，源请求 5 秒超时，成功响应 CDN 缓存 60 秒；可见页面每分钟检查，切换食堂直接使用对应来源的最新状态，离开页面停止轮询，返回时立即更新。源更新时间超过 30 分钟、数据无效或请求失败时显示“暂无数据”，不保留旧人数，也不会影响菜单。此功能无需密钥，不使用每日翻译任务或 Blob。

食堂页顶部采用较矮的全宽搜索与校区选择区，列表高度约容纳 3 行食堂条目，更多结果在列表内滚动；电脑端每行最多 3 个餐厅，手机端单列。地图开关放在同一选择模块右上角，默认收起；电脑端展开后地图占据模块右侧、列表缩至左侧，收起后列表恢复全宽；手机窄屏在同一模块内上下排列。首次展开才初始化底图与标记，之后展开会重新核对显示尺寸及当前筛选，继续与列表和菜单联动。支持中文校区别名、德文名称和街道搜索，主标题显示完整原名，下方显示地址。搜索框右侧仅保留校区筛选；14 个校区或片区保持同一层级，下拉筛选与列表采用统一的 RCI 使用场景顺序：Garching、主校区、LMU 大学区、奥林校区、Weihenstephan，随后为其余慕尼黑及周边地点，外地校区在最后；这是产品初始排序，不基于个人浏览记录或实际访问量。Garching 使用相同样式，默认筛选仍为「全部校区」。分类标签由同一份定义生成下拉框、列表与无需 JavaScript 的备用选项；`content/canteens.json` 记录校区归属、搜索别名及核对来源。校区可与搜索组合，匹配数量、列表和地图标记同步更新。主动选择仅收录一家餐厅的校区时，若该餐厅匹配当前搜索便自动切换菜单；多餐厅校区和输入搜索词时保留当前菜单。当前校区搜索为空、其他校区有匹配时，在原列表位置提示校区与数量，点击「查看结果」仅解除校区限制并保留搜索词，列表、地图与数量同步更新，由用户选择菜单；所有校区都无匹配时可一键清除筛选。定位当前食堂时如其被筛掉则恢复全部。列表选择保留搜索、筛选和滚动位置，地图选择会显示并高亮对应列表项；列表始终按校区分组，校区内依次排列食堂（Mensa）、小餐厅（StuBistro）、咖啡厅、其他餐厅，同类再按名称排序，备用下拉选择也使用此顺序，不再设置「最近查看」分组或依据浏览记录置顶；仅在本地键 `rci.mensa.recent.v1` 保留最后选择的 1 个食堂（兼容旧记录），普通入口恢复该选择，链接中的有效食堂参数优先；没有历史记录时使用目录首项，不再固定指定 Garching。Leaflet 1.9.4 与 Leaflet.markercluster 1.5.3 随静态构建提供，仅食堂页加载，保留开源许可证。地图使用 eat-api 提供的 25 个食堂坐标和 OpenStreetMap 标准瓦片，保留地图署名；点击标记切换菜单，列表选择同步定位和高亮，邻近标记可放大或展开。地图无需定位权限，底图或地图资源不可用时保留列表与菜单。日期、价格与中文缓存逻辑保持原有方式。

菜单中文由每日后台任务补充，界面无需额外操作：`api/mensa-sync.js` 每天 09:30 UTC 所在时段检查本周及之后两周的所有已收录食堂，只对未收录的新菜名调用 Vercel AI Gateway，并将完整德文菜名对应的中文持久保存到现有私有 Blob 的 `mensa/v1/` 命名空间。大小写、空白及 Unicode 规范形式相同的菜名复用一份翻译；人工整理的 `content/mensa-zh.json` 优先。`api/mensa-translations.js` 只提供指定食堂和周的中文缓存，页面先显示原菜单，再补充缓存；翻译服务失败不会阻止查看菜品、价格或原菜单。缓存没有时暂时显示德文；后台按天继续补充。可用 `node scripts/check_mensa_translations.js` 单独审核人工词典的漏译，该脚本不计入云端缓存。

定时更新由 `vercel.json` 中每日一次的 Cron 驱动，生产部署后生效。配置 `CRON_SECRET`（至少 32 个随机字符）保护后台入口，以及现有 `BLOB_READ_WRITE_TOKEN`；Vercel 部署自动提供 `VERCEL_OIDC_TOKEN` 调用 AI Gateway，无需另外维护模型密钥。默认模型 `google/gemini-2.5-flash-lite`，可通过 `MENSA_TRANSLATION_MODEL` 调整；本地在已关联的项目中执行 `vercel env pull .env.local` 刷新临时身份，或配置仅服务端使用的 `AI_GATEWAY_API_KEY`。`MENSA_TRANSLATION_DAILY_LIMIT` 默认 200，允许 0–250，按柏林日期持久记录已尝试翻译的菜名数，失败和手动重试也占用当天额度；超额的新菜名留待后续日期。同步使用持久租约避免重入，已完成的当天任务不会重复抓取；经认证的 `GET /api/mensa-sync/?force=1` 可重新检查，但仍受当天翻译额度限制。首次上线前应运行一次认证同步来填充缓存。所有凭据仅放在 Vercel 环境变量或忽略的 `.env.local`，不会进入静态页面。

菜单空状态区分「公告休息」「周末休息」「通常休息」「暂无数据」和「读取失败」。周视图保留七天，无菜单的周六、周日默认显示「周末休息」并置灰；默认进入页面或点击「今天」遇到周末时自动寻找下一次已发布菜单，手动选择的日期仍保留，实际发布的周末菜品仍正常展示。`content/mensa-availability.json` 保存 2026-10-18 人工核对的 21 个 Studierendenwerk 食堂的常规营业日及 2026/27 圣诞、新年休息公告，并提供各自官方营业页面；公告提示包含核对日期与休息起止日期。这不是完整假期或临时停业日历，菜单每日同步不更新公告文件；没有公告记录不能据此断言营业，另外 4 个食堂同样采用周末默认休息的展示规则，其他假期或停业原因没有核对资料时保持待确认。API 的 404 仅表示本周没有菜单数据；空菜品也可能是上游遗漏，不直接称为「未公布」。网络、服务或数据格式错误单独显示读取失败与重试；查找下周失败时保留已读取的本周状态。实际发布的菜品始终优先展示。

## 自动选课与学分规划

「我的计划」直接展示学分概览与学期看板。顶部「一键规划」直接按当前条件计算并更新看板，成功后提供变动摘要、查看方案和撤销，无需先进入条件页或再次采用。首次缺少入学时间或补修确认时，只补充必要信息，点击「开始规划」即计算；学期数和起始季节收在可展开的学期安排中，默认按现有时间范围规划。按钮旁的条件图标是可选入口，可调整学业信息、想选／排除、语言与负担，也可选择先预览再采用。保留「添加课程」「更多」，与「一键规划」及条件入口统一为同高操作栏，电脑端与标题对齐，手机端置于标题下方；第二行展示入学时间、学期数、保存状态及学业规则。规划按钮的说明继续提供给辅助阅读，不再单独占用可见行。移除独立计划设置、已修课程入口与步骤条。已通过状态直接在课程卡片记录，电脑端保留原学期，手机端在看板下方折叠查看，可修正历史学期、改回待修并撤销。弹窗保持挂载，搜索、条件草稿与看板滚动位置保留。课程面板每次展示30门，搜索覆盖完整目录。

计划统一为 v5，兼容旧 v2 / v3 / v4，继续使用原存储键、跨页锁、备份 journal 与最近三份恢复记录。电脑端已通过课程继续显示在原学期，以「已通过」区分；学分计入已修，从未来负担排除。通过学期未知或超出当前规划范围的记录另行显示，历史学期不自动改写。可拖动已通过课程或在卡片中修正通过学期，保留通过状态，不受当前开课季节限制；下拉选项也支持未记录和规划范围外的历史学期，调整可撤销。状态仍可改为待修。新版本号阻止仍打开的旧版页面覆盖新的分类分配，旧页面应刷新后继续。退役的时间字段仅作旧备份兼容保留，不再影响规划，也不进入普通分享链接。

一键规划复用当前已保存的负担、语言、想选／排除和单学期条件；新计划沿用验证后的默认条件，不猜测个人入学或补修要求。必要信息只需确认一次，补齐后直接计算；取消不启动计算。条件页是可选入口，「一键规划」按当前草稿计算并更新；「先预览」保持只读，采用后才保存。首次学业信息保存及缩短范围仍保留课程移动确认和历史保护。计算中禁用重复启动，可取消；失败保留原计划并提供具体冲突，支持调整条件再试。所有自动写入均核对计算前的完整计划快照，跨页面变动时拒绝覆盖；成功后的撤销同样核对结果快照，恢复课程、偏好、固定安排和已修记录，不能覆盖后续修改。设置并发冲突时保留草稿并提示重新载入。

自动规划内的「使用默认条件」将默认负担填入当前草稿（每学期 0–32 ECTS、估算 0–6 次考试）、英语与德语、允许按通常学期安排尚未公布开课的课程，并重新检查标准进度，同时清除单学期覆盖。学业信息、计划学期数、已修、已选课程及固定安排、想选／排除记录保留。开始规划学期取范围内不早于已修记录的最早学期；已修历史超出规划范围时仍需先核对，不能绕过生成器检查。必要入学信息缺失时仍要求确认，不自行猜测补修。填入默认条件后留在条件页查看和调整，生成只展示预览，采用后才保存。

可选的自动方案预览沿用设置页的卡片与固定操作区：先查看规划学分、已修／待修、预计完成学期和课程变动，再按学期核对每门待修课程的学分、新增／调整与固定标记。确认事项默认展开，长列表只在内容区滚动；手机端改为单列，右上角关闭按钮和底部「返回调整条件」「采用方案」持续可见；关闭预览不采用方案，生成中关闭会停止计算。未生成成功时突出返回调整条件，成功时突出采用方案。加载、未找到方案与补修冲突保持相同界面结构，手机端也可直接核对补修设置。原计划仅在采用后更新，已有变更检查和撤销保护继续生效。

`assets/planning-engine.js` 在 Worker 内补齐必修、Robotics 二选一、G/H/I 最低额、J、K 与论文，并处理排除、语言、开课季节、全局／单学期 ECTS 及估算考核数、固定学期与标准进度。已修、固定课程和自录认定保留；想选课程优先纳入，未固定的目录选修可被替换，在可行范围内尽量减少已有选修的变动。无法纳入的想选逐门显示原因，并继续留在偏好中供下次规划。方案详情列出替换的已有选修、按排除偏好移除的课程及想选覆盖；一键规划成功后直接更新，可选预览在采用前不改动看板。失败先检查完整规划范围的固定学期、开课／语言交集、学分与考核容量，显示课程名称、实际需求和上限，不展示搜索早期淘汰候选的课程代码列表。已核对的跨类别模块只计一次，显式分类与已修分类保持不变。结果采用时检查是否已有其他修改；搜索与候选组合均有预算，达到上限会明确说明，不把未找到方案当成无解或全局最优。

论文优先独立安排在最后学期；同学期有其他课时仍需核对考核顺序与提前开题批准。进度按本模型的分类上限预测，已知通过学期不会提前计入；超额选修不替代缺失必修。可选择只提示标准进度期限；这不表示学校已批准延期，也不判断未达期限后的行政后果。论文正常期限为正式出题起最多六个月；延期或停算按学校批准记录核对，实际日期及期限以学校记录为准。

### 站内反馈接收与本地验证

完整预览先执行 `npm ci`、`node scripts/build_site.js`，再运行 `npm run dev`，打开终端显示的 `http://127.0.0.1:8001`。原 Python 静态服务器仍可预览正文，但不能接收反馈，提交失败时页面会保留文字。

反馈接收使用 Frankfurt 的 Vercel 私有 Blob store。为 Preview / Development 和 Production 分别连接私有存储，设置服务端 `FEEDBACK_RATE_LIMIT_SECRET`，再重新部署；不要把生产存储凭据分享给预览环境。可使用自动注入的 Blob OIDC 凭据或 `BLOB_READ_WRITE_TOKEN`，凭据仅在服务端使用。`vercel env pull .env.local --yes` 供本地预览使用，`.env.local` 不进入 Git 或发布文件。未配置接收端时明确返回失败，不会显示已收到。

维护者在 Vercel 项目的 Storage 中打开对应私有 store，查看 `feedback/` 下的 JSON，按 `createdAt` 处理；不会自动创建公开 Issue 或发送邮件。`feedback-rate/` 仅含加密摘要构成的短时限流键及清理时间，不保存原始 IP；同一网络每 10 秒可提交一条。维护时可删除超过 24 小时的限流标记。反馈使用随机回执与正文摘要防止网络重试重复保存。反馈与处理状态均只允许管理员接口读取。

发布检查含 `node tests/feedback.test.js`：验证私有写入、回执、重试去重、输入和来源校验、限流以及失败保留文字。测试使用内存模拟；实际接收需另在非生产存储验证。


### 管理员反馈收件箱

管理员通过私下保存的登录信息或浏览器书签访问；普通用户页面不展示管理入口，管理页不进入站内搜索和 sitemap，并声明 noindex。仅有一个管理员密码，不开放注册。登录后查看反馈原文、类型、来源页面和时间；可筛选「待处理／处理中／已处理」，逐条保存状态并退出登录。较多反馈分页加载，状态筛选同样支持继续加载更早记录。

首次本地配置运行 `node scripts/setup_feedback_admin.js`，脚本生成强随机密码，将登录信息放在仅当前 Mac 账户可读取的 `.vercel/feedback-admin-login.txt`，将密码的 scrypt 摘要和独立会话密钥加入 `.env.local`。明文密码不进入 Git、静态构建或 Vercel 环境变量。启动本地预览前需重启 `npm run dev`。

脚本同时生成 `.vercel/feedback-admin-env-0.json` 和 `feedback-admin-env-1.json` 两份私有请求体，用 Vercel 环境变量 API 逐份同步到已核对的本项目 Development / Preview，成功后删除临时请求体。Production 使用独立密码、会话密钥和私有 store。部署需同时配置 `FEEDBACK_ADMIN_PASSWORD_HASH`、`FEEDBACK_ADMIN_SESSION_SECRET`、`FEEDBACK_RATE_LIMIT_SECRET` 及 Blob 凭据；不要将这些值放入客户端。

生产首次配置使用 `node scripts/setup_feedback_admin.js --production`，不会更改本地／预览密码或 `.env.local`。正式登录信息单独保存在 `.vercel/feedback-admin-production-login.txt`，三个私有请求体只以 Secret 类型同步到 Production，同步后删除请求体。生产重置需明确运行 `--production --reset`，同步并重新部署后旧生产会话失效。

忘记管理员密码时可在本机明确执行 `node scripts/setup_feedback_admin.js --reset`，同步新的环境配置并重新部署。更换密码摘要后旧会话失效。登录保持最多 8 小时，使用 HttpOnly / SameSite=Strict Cookie；线上 Cookie 使用 Secure 与 __Host 前缀。会话保存在私有存储，退出会撤销当前会话。登录限流每个网络每 15 分钟最多 5 次，不记录原始 IP。敏感接口设置 no-store，每次读取或修改均重新验证会话；修改还需要同源和 CSRF 校验。

处理状态单独保存在 `feedback-status/`，不改写用户反馈原文。保存采用 ETag 条件写入，另一页面已修改时返回冲突并要求刷新，不静默覆盖。管理员界面把反馈当纯文本显示；反馈、会话与凭据都不会写进静态 HTML、搜索索引或个人计划备份。


### 网站访问统计
