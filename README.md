# TUM RCI All-in-One

## [打开学生网站 → tum-rci-all-in-one.vercel.app](https://tum-rci-all-in-one.vercel.app/)

给 TUM RCI 同学的中文日常入口。独立学生社群项目，不隶属于 TUM。

## 第一版，只做好两件事

**常用网站入口**：打开首页就能找到 TUMonline、Moodle、Matching、TUM Live 等平台。每个入口写清用途，点击卡片直接打开；按「上课与选课」「图书馆与校园」「科研与协作」「咨询与支持」直接分区展示，支持用途搜索。已收藏的网站卡片直接展示在首页顶部，点击即可打开；下方继续按模块展示全部网站。

图书馆入口直达 OPAC 检索和 anny 预约登录，卡片另有官方预约说明；预约支持自习座位、小组讨论室与视频间。eAccess 用于校外读取已许可电子文献，dokumenTUM 提供馆藏纸本文献扫描申请步骤。首页另有论文题目平台、MATLAB 校园许可、TUM ShareLaTeX、LRZ GitLab、Sync+Share 和 GigaMove，卡片注明用途与登录条件，MATLAB 卡片另有官方激活与安装说明；来源台账记录公开核对范围。

首页「RCI 学业咨询」直达 RCI 专业页联系人区域，注明专业协调员与 rci@tum.de；沿用 R009 收藏编号。原 Informatics 总页以「Informatics 咨询总览（多专业）」保留在更多资料中，并说明其跨专业考试事务清单对 Master RCI 的例外。

另收录 MPIC 学生会课程评价查询、考试专用 Moodle、CIT 打印与扫描说明、英语写作辅导预约、Academic Coaching、文献管理校园许可、图书馆文献咨询和 ProLehre 学习方法。电脑端将论文入口区分为「研究组论文题目」（Thesis Management，参与平台的研究组）与「全校论文题目公告栏」（Themenbörse，跨学院发布），两者都不保证覆盖全部题目；原论文入口的收藏编号保留。图书馆预约也注明主校区 Presentation Lab 的演讲练习用途；需要个人登录或申请的服务，只核对公开入口，不转载个人结果。

**如何选课、如何规划学分**：先看懂学分结构，再找到课程，以横向学期看板分配课程，随时看每学期学分与整体缺口。支持四、五学期等不同节奏，选择起始冬夏季节，按目录季节检查安排。课程以目录原名显示，中文译名辅助理解，模块代码用于核对；类别保留分组字母与原名。实验课、研讨课和考试登记的办理路径分开说明。

首版 Goal：**让学生一打开就知道在哪里点，点完知道下一步做什么，能顺畅地找到常用网站并完成自己的选课与学分规划。** 验收以入口清晰和实际操作顺畅为准，功能或资料数量不作为产品完成标准。

[常用网站](https://tum-rci-all-in-one.vercel.app/) · [选课程](https://tum-rci-all-in-one.vercel.app/courses/) · [我的计划](https://tum-rci-all-in-one.vercel.app/planner/)

电脑端将学分要求与选课指南并入「我的计划」：顶部进度显示个人学分结构，「选课与学分说明」按需查看规则、Matching 与考试报名步骤。顶部导航保留三个主入口；旧 `/study/` 链接进入计划页说明，窄屏原有指南保持可用。

手机端有固定的常用网站、选课指南、我的计划入口。加入课程后按钮和学分同步更新；二选一课程可以确认改选，移除课程可以撤销。

「选课程」输入名称或代码即搜索；必修、专业选修、跨学科可一键切换，季节、语言和计划状态收在更多筛选中。目标学期持续可见，课程旁直接加入或移到本学期，可连续选课并撤销。筛选和目标学期保留在网址中，清除筛选不会改动目标学期；手机端按单列显示。从列表进入详情后，页面返回和浏览器后退会恢复已加载的课程数量及原课程在屏幕中的位置，焦点也回到该课程。视图状态仅保存在当前标签页和浏览历史中，不写入个人计划；无法读取暂存时仍能按课程定位。

课程详情页先展示课程名称、中文简介和学分／开课季节／授课语言，再阅读上课与考核、选课要求和预计投入。电脑端把目标学期和加入计划放在右侧固定区域，手机端使用简介下方的紧凑操作区。具体先修、二选一、学分冲突和个人资格要求直接显示，旧版说明放在简介之前；重复的通用提示和没有数据的时间栏不显示。已知二选一、等价课程及同一计分组的其他版本提供名称、代码、学分和详情链接。可直接加入或移动课程，并撤销本次调整；已修和自录记录保护不变。本学期开课与官方课程介绍有独立入口，返回列表保留搜索和筛选。

`content/course-summaries.json`覆盖全部595条已收录课程，逐门整理原创中文简介、上课方式、考试方式及预计投入。593条对应官方模块手册（含补查的ED140014、MW2352、WI000159）；IN2404按2023年官方课程页补充内容和上课方式，IN9003仅按RCI法规附件补充上课和考试信息。549条有官方内容简介，45条手册没有内容字段，IN9003尚未找到课程内容，缺项明确显示、不按课程名称编写。教学、考核和时长独立处理；旧学期说明有醒目标记，ED150018、SZ0514的时长冲突不作为有效总投入发布。总投入是整个模块的估算，不是每周课时，不能代替本学期公告。

`data/course-content-evidence.json`保存来源身份、原始响应与选用字段哈希、学期、缺项和冲突判断，不保存官方全文。构建时校验595条完整覆盖、来源与目录证据一致、字段可用性和时间分项，避免漏课或用空白字段生成简介。逐字段核查、哈希和对照日期不渲染到用户页面；会影响选课的先修、学分冲突、等价课程和资格限制继续直接显示。MA8113、IN3150、SOT56601、SOT82136继续按维护者要求排除。

个人计划和收藏自动保存在当前浏览器，无需登录。首页收藏区与「我的计划」中的「备份与迁移」可导出包含课程、学期安排、批次、补修设置和收藏的 JSON 文件，换设备后导入即可继续。导入先显示预览，默认合并并保留当前课程的安排与状态，也可选择替换。每次导入前保留一份本地恢复备份，最近 3 次记录可预览恢复。旧版计划文件仍可使用，不改变当前收藏；电脑端旧计划中缺少学期安排的未修课程放入第1学期，已修历史学期保留。

网站区旁的「缺少入口？」、桌面页头和全站页脚可进入快速反馈。先选择缺少入口、功能建议或使用问题，再填写简短描述；反馈直接提交到本站私有收件箱，无需账号，仅供维护者查看。保存成功后显示回执；失败时保留文字，可安全重试。只提交描述、类型和相关页面路径，不附带个人计划、收藏、搜索词或分享片段。

已有申请、科研、生活等资料保留在次级页面与更多资料中。后续按实际需求逐步完善。

## 首版验收路径

- 打开首页，能看懂常用平台的用途，一次点击进入原始网站。
- 收藏一个网站，立即看见它出现在首页顶部，点击卡片直接打开；原有收藏保留，取消收藏可以撤销。搜索无结果时能清除搜索继续使用。
- 从选课指南理解学分结构，进入课程目录，按课程名或代码找到课程。
- 选择四或五学期与起始冬夏季节，每学期一列，课程向下排列；卡片默认只显示名称和学分，拖动或点开课程选择目标学期，选完自动收起，支持撤销。标题和学分在滚动时持续可见，手机左右滑动查看其他学期、点课程调整。目录季节不符时先确认。
- 点学期卡片上的「添加课程」，直接打开选课面板。默认展示对应季节，可连续加入多门，学分即时更新；已有课程可直接移到本学期，也可撤销。电脑端缩短规划时，超出范围的未修课程移到第1学期，课程与学分保留。
- 先录入已修、个人补修与选课偏好，自动方案预览后可采用；用手动看板继续调整，实际课表在个人 TUMonline 查看。
- 手机端入口持续可见，操作不被浮栏遮挡；刷新后已有计划仍可继续。

详见 [CONTENT_POLICY.md](CONTENT_POLICY.md)、[PUBLISH.md](PUBLISH.md) 和 [RELEASE_V3.md](RELEASE_V3.md)。

跨页面修改优先使用 Web Locks；不支持时使用 IndexedDB 读写事务互斥，现有计划、收藏与恢复备份仍保留在原 localStorage 格式。两种锁均不可用时只保留本页临时数据并允许导出，拒绝持久导入；不会无锁写回旧记录。升级前已打开的旧页面请刷新后再继续编辑。

## 自动选课与学分规划

3.11.0 将「我的计划」改为直接展示学分概览与学期看板。顶部「添加课程」可连续选课；「自动规划」首次仅引导确认必要设置，再预览和采用方案。「已修」和「选课偏好」独立打开，语言、负担及规则说明收在计划设置中；Excel、PDF、分享和完整备份恢复统一放在「更多」。弹窗保持挂载，跨页面更新时保留搜索、未保存的负担设置及看板滚动位置。课程面板分批展示，每次30门，搜索仍覆盖完整目录。

计划统一为 v5，兼容旧 v2 / v3 / v4，继续使用原存储键、跨页锁、备份 journal 与最近三份恢复记录。电脑端已通过课程继续显示在原学期，以「已通过」区分；学分计入已修，从未来负担排除。通过学期未知或超出当前规划范围的记录另行显示，历史学期不自动改写。可拖动已通过课程或在卡片中修正通过学期，保留通过状态，不受当前开课季节限制；下拉选项也支持未记录和规划范围外的历史学期，调整可撤销。状态仍可改为待修。新版本号阻止仍打开的旧版页面覆盖新的分类分配，旧页面应刷新后继续。退役的时间字段仅作旧备份兼容保留，不再影响规划，也不进入普通分享链接。

「调整规划条件」依次展示学业信息、常用规划偏好与可展开的低频条件。电脑端同组字段横向排列，手机端按两列和整行组合，底部保存按钮持续可见。120 ECTS 平均参考压缩为一行说明，避免挤占常用控件空间。学业信息、负担、语言偏好和所有单学期设置统一在点击底部「保存设置」或「保存并预览」后生效；输入框标明 ECTS／次数单位。高级要求在独立展开区域中，通过原生表单关联与常用偏好一并保存，跨页面更新仍保留草稿。必要信息补齐后提醒自动消失，补修冲突说明继续保留；单学期负担切换时保留各学期草稿，缩短计划时将选择移入有效范围；实际课程移动在保存时确认，已通过课程的历史学期保留。关闭或离开有修改的设置页会提醒，放弃后恢复原设置；保存失败保留草稿，其他页面的课程更新可合并，设置冲突则提示载入最新设置。条件保存与方案采用仍分开，先看预览再决定是否采用。

顶部「使用默认偏好」将模型默认负担填入当前草稿（每学期 0–32 ECTS、估算 0–6 次考试）、英语与德语、允许按通常学期安排尚未公布开课的课程，并重新检查标准进度；同时清除单学期覆盖与未保存的规划条件草稿。学业信息、计划学期数、已修、已选课程及固定安排、想选／排除记录保留。开始规划学期取范围内不早于已修记录的最早学期；已修历史超出规划范围时仍需先核对，不能绕过生成器检查。必要入学信息缺失时仍要求确认，不自行猜测补修。填入默认偏好后留在原页面查看和调整，点击底部按钮才保存；「保存并预览」随后生成方案，自动推荐课程仅在采用方案后更新。

自动方案预览沿用设置页的卡片与固定操作区：先查看规划学分、已修／待修、预计完成学期和课程变动，再按学期核对每门待修课程的学分、新增／调整与固定标记。确认事项默认展开，长列表只在内容区滚动；手机端改为单列，调整条件、返回与采用按钮持续可见。加载、未找到方案与补修冲突保持相同界面结构，手机端也可直接核对补修设置。原计划仅在采用后更新，已有变更检查和撤销保护继续生效。

`assets/planning-engine.js` 在 Worker 内补齐必修、Robotics二选一、G/H/I最低额、J、K与论文，并处理想选／排除、语言、开课季节、全局／单学期ECTS及估算考核数、固定学期与标准进度。已核对的跨类别模块只计一次；显式分类与已修分类保持不变，未分配的未来模块可在获准类别间选择。结果先预览，采用时检查是否已有其他修改。搜索和候选组合均有预算，找不到方案不证明无解或全局最优。

论文优先独立安排在最后学期；同学期有其他课时仍需核对考核顺序与提前开题批准。进度按本模型的分类上限预测，已知通过学期不会提前计入；超额选修不替代缺失必修。可选择只提示标准进度期限；这不表示学校已批准延期，也不判断未达期限后的行政后果。论文正常期限为正式出题起最多六个月；延期或停算按学校批准记录核对，实际日期及期限以学校记录为准。

`data/teaching-offerings.json` 只保存对应学期的开课／语言证据，不包含周课时。`data/course-overrides.json` 保存当前分类、周期与待复核状态，保留法规CSV历史值。典型周检查、个人时间编辑、ICS交换和规划中的时间筛查已移除；实际课表到TUMonline的Terminkalender查看。

### 站内反馈接收与本地验证

完整预览先执行 `npm ci`、`node scripts/build_site.js`，再运行 `npm run dev`，打开终端显示的 `http://127.0.0.1:8001`。原 Python 静态服务器仍可预览正文，但不能接收反馈，提交失败时页面会保留文字。

反馈接收使用 Frankfurt 的 Vercel 私有 Blob store。为 Preview / Development 和 Production 分别连接私有存储，设置服务端 `FEEDBACK_RATE_LIMIT_SECRET`，再重新部署；不要把生产存储凭据分享给预览环境。可使用自动注入的 Blob OIDC 凭据或 `BLOB_READ_WRITE_TOKEN`，凭据仅在服务端使用。`vercel env pull .env.local --yes` 供本地预览使用，`.env.local` 不进入 Git 或发布文件。未配置接收端时明确返回失败，不会显示已收到。

维护者在 Vercel 项目的 Storage 中打开对应私有 store，查看 `feedback/` 下的 JSON，按 `createdAt` 处理；不会自动创建公开 Issue 或发送邮件。`feedback-rate/` 仅含加密摘要构成的短时限流键及清理时间，不保存原始 IP；同一网络每 10 秒可提交一条。维护时可删除超过 24 小时的限流标记。反馈使用随机回执与正文摘要防止网络重试重复保存。反馈与处理状态均只允许管理员接口读取。

发布检查含 `node tests/feedback.test.js`：验证私有写入、回执、重试去重、输入和来源校验、限流以及失败保留文字。测试使用内存模拟；实际接收需另在非生产存储验证。


### 管理员反馈收件箱

管理员通过私下保存的登录信息或浏览器书签访问；普通用户页面不展示管理入口，管理页不进入站内搜索和 sitemap，并声明 noindex。仅有一个管理员密码，不开放注册。登录后查看反馈原文、类型、来源页面和时间；可筛选「待处理／处理中／已处理」，逐条保存状态并退出登录。较多反馈分页加载，状态筛选同样支持继续加载更早记录。

首次本地配置运行 `node scripts/setup_feedback_admin.js`，脚本生成强随机密码，将登录信息放在仅当前 Mac 账户可读取的 `.vercel/feedback-admin-login.txt`，将密码的 scrypt 摘要和独立会话密钥加入 `.env.local`。明文密码不进入 Git、静态构建或 Vercel 环境变量。启动本地预览前需重启 `npm run dev`。

脚本同时生成 `.vercel/feedback-admin-env-0.json` 和 `feedback-admin-env-1.json` 两份私有请求体，用 Vercel 环境变量 API 逐份同步到已核对的本项目 Development / Preview，成功后删除临时请求体。Production 使用独立密码、会话密钥和私有 store。部署需同时配置 `FEEDBACK_ADMIN_PASSWORD_HASH`、`FEEDBACK_ADMIN_SESSION_SECRET`、`FEEDBACK_RATE_LIMIT_SECRET` 及 Blob 凭据；不要将这些值放入客户端。

生产首次配置使用 `node scripts/setup_feedback_admin.js --production`，不会更改本地／预览密码或 `.env.local`。正式登录信息单独保存在 `.vercel/feedback-admin-production-login.txt`，三个私有请求体只以 Secret 类型同步到 Production，同步后删除请求体。生产重置需明确运行 `--production --reset`，同步并重新部署后旧生产会话失效。

忘记管理员密码时可在本机明确执行 `node scripts/setup_feedback_admin.js --reset`，同步新的环境配置并重新部署。更换密码摘要后旧会话失效。登录保持最多 8 小时，使用 HttpOnly / SameSite=Strict Cookie；线上 Cookie 使用 Secure 与 __Host 前缀。会话保存在私有存储，退出会撤销当前会话。登录限流每个网络每 15 分钟最多 5 次，不记录原始 IP。敏感接口设置 no-store，每次读取或修改均重新验证会话；修改还需要同源和 CSRF 校验。

处理状态单独保存在 `feedback-status/`，不改写用户反馈原文。保存采用 ETag 条件写入，另一页面已修改时返回冲突并要求刷新，不静默覆盖。管理员界面把反馈当纯文本显示；反馈、会话与凭据都不会写进静态 HTML、搜索索引或个人计划备份。


### 网站访问统计

Vercel 项目已启用 Web Analytics，页面按 Other 指引使用 `@vercel/analytics` 的 `inject()`。构建时将锁定版本的官方浏览器模块及 MIT 许可一起发布为同源静态资源，不需要 React 或额外打包器。只有 `VERCEL_ENV=production` 且当前源站匹配正式域名时才启动；本地、Preview 与管理员页面不采集。

只统计公开页面浏览，不发送个人计划、收藏或反馈正文，也不记录按钮等自定义事件。`beforeSend` 会移除页面 URL 的全部查询参数和片段，并拒绝管理员、API 与外站 URL。Referrer-Policy 使用 strict-origin，来源只保留域名。当前项目在 Vercel Analytics 中查看访客、浏览量和热门页面；统计从接入后开始，事件费用按团队套餐计费。

`node tests/analytics.test.js` 验证数据过滤与环境隔离，已纳入发布检查。上线后访问公开页面，检查官方脚本和采集请求，再在 Analytics 页面确认收到数据。

管理员登录后，同一管理页显示近 7 天／30 天的访客数、浏览量、每日趋势与热门页面。数据由 `/api/admin-analytics` 从官方 Web Analytics API 读取，沿用反馈管理的服务端会话验证，不另行采集访问。仅查询固定的本项目 Production 数据，日期按 UTC 划分并包含当天；总访客数使用整个期间的去重结果，不能相加每日访客数或各页面访客数。每个范围在函数实例内最多缓存一分钟；接口与页面数据不进入公开缓存。

Production 需额外配置服务端 Secret `ANALYTICS_VERCEL_TOKEN`，使用范围仅限本项目的独立 Vercel Access Token。不要复用个人全账号 Token、放入静态资源或把生产凭证同步到 Preview / Development。Token 到期或撤销后需替换 Secret 并重新部署。未配置、权限不足或上游失败时显示明确错误，保留上次成功显示的数据；退出、会话过期与离开页面时清空统计展示。公开页面继续不展示管理入口。

`node tests/admin-analytics.test.js` 验证匿名与伪造会话被拒绝、固定查询范围、当天数据边界、服务端缓存与失败关闭，已纳入完整发布检查。
